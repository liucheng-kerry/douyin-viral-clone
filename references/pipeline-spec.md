# 阶段衔接契约（pipeline-spec）

各阶段之间的数据接口。上一阶段的产出就是下一阶段的输入，格式对不上就跑不通。

## 阶段 1 → 阶段 2（拆解 → 脚本）

**输入**：`01-拆解/` 下的 `frame-table.md`（逐帧拆解表）+ `breakdown.md`（含镜头段级时间轴拆解表）。

脚本阶段只取四样：
1. 爆款公式中的**段落结构模板**（钩子→铺垫→转折→CTA 的段落划分与每段时长）
2. **镜头段级时间轴**的节奏数据（每段几秒、切点密度、钩子出现秒数）
3. **画面公式**（景别/机位/运镜序列、色调、场景数——逐帧拆解表合并出的镜头段）
4. **逐帧拆解表**中可迁移的构图与道具细节（写脚本"画面内容"列时直接引用）

替换规则：**结构照搬、画面全换、台词可重写但意思必须与原片一致**。逐段对照镜头段级时间轴写新表的"画面内容"列（主角/场景/道具全换）。

台词的三个动作：
1. **"口播/台词"列写"能念的改写句"**，不是原句——原句在 `01-拆解/audio.txt` 里当"意思基准"用
2. 同时产出 `02-脚本/dialogue-map.md`（台词语义对照表：原句 / 改写句 / 改了什么 / 判定），表格上方声明 `档位：A/B/C`
3. 跑 `python scripts/dialogue_check.py --map 02-脚本/dialogue-map.md --audio 01-拆解/audio.txt`，**error 必须清零**才能进阶段 3

改写幅度的三档（按复刻方式选）：档 A 轻改（只动量词/称呼）、档 B 改写（换主语视角与名物）、档 C 重写（字面全重写，保句子功能与信息结构）。三档共用五条锚点（信息点/意图/情绪强度/人称关系/句数落点）与四条技术要求（字数 ±30%、单句 ≤12 字、能说出口、不写翻译腔）。

时长默认**不动**（台词的改写版按原句长度对齐，时间轴就还在）；只有画面动作确实需要更多时间才 +20%，且必须回头确认这段台词还塞得下（一段台词量不超过时长的 1/3）。

## 阶段 1 → 阶段 1.6（拆解 → 风格锚）

**输入**：`01-拆解/video/` 下的原片 + `frame_*.jpg`。

```bash
python scripts/style_anchor.py --video "01-拆解/video/<文件>" --out "01-拆解" --frames 12
```

**产出**：
- `01-拆解/style-anchor.md` —— 量化数据表（亮度/对比度/饱和度/色温/锐度/高光暗部/主色相）+ 主色板 Top6 + **风格句** + **负向风格词** + 画风判定表 + 质检三问
- `01-拆解/style-swatch.svg` —— 主色板可视化

**必填空**：脚本只给数值，"画风/镜头质感/光源"三行必须由 agent 用 ViewImage 看帧后补齐，补完可用 `--style-word` 重跑刷新风格句。

**下游契约（硬性）**：阶段 3 每张图片提示词，以及阶段 4 每段提示词，**必须原样包含风格句的色调词并带负向词**。落地位置取决于选的是 yyl 哪种写法（别一概而论）：

| yyl 写法 | 风格句写进哪个字段 |
|---|---|
| A 一镜到底（《丹眉》式） | 【光影与风格】的「光线方向 + 冷暖 + 饱和/对比 + 颗粒/景深」几项，用风格句原词 |
| B 多分镜（六块结构） | 拆两处：「色彩与影调」← 风格句的色调/饱和/对比/主色；「视觉基调」← 画风判定表的画风 + 镜头质感（该字段本义是摄影机+镜头，不要塞整句色彩统计） |

同一支片子的各段之间这几行要**逐字一致**，这是全片风格统一的锚点。

## 阶段 2 → 阶段 3（脚本 → 图片资产）

**输入**：`02-脚本/script.md` 的分段时间轴表 + `02-脚本/dialogue-map.md`（语义对照表，`dialogue_check.py` 的 error 必须清零）。

从表中提取资产清单：
- **角色**：每段出现的主体人物。**一个角色只出一张图**——单张定妆照（全身正面、身体略侧 15°，脸与服装结构同时可读），跨段锁定一致性。
- **场景**：发生地点变化处建场景图，**一个场景一张定场图**（该场景最常复用的机位，画里不放人），同场景多段共用。
- **关键道具/首帧**：表里"画面内容"列提到的特写物、开场画面。道具一张特写；首帧是**每段一张**单画面（不提前批量做）。

资产清单先列成表（资产名 | 图型 | 比例 | 出现段号 | 锁定要素）再逐个写提示词。提示词正文要能直接回答该资产在视频提示词中"锁定什么、不用什么"。

**提示词规范 = `ai-drama-reference-art`**（本机已装；未装时按 SKILL.md 3.2.1–3.2.4 同口径自行编写）：

- 主角 = **单张整图**（一张图只装一个视角），棚拍规则（纯色冷灰 `#606570`、单一主光左上 45°、可留极弱环境反射、冷钢蓝、全身不裁头脚、画面无任何文字）
- 场景 = **单张定场图**（单点锚定 / 色卡统一 / 至少三个空间锚点可推断 / 绝对语言；画里不放人，免得 `@Image2` 把人也锁进去）
- 两者共有：影视参考锚定、姿势=心理状态（不写物理位置）、DNA 物件、色卡融入叙述并保留色号、MATERIAL TRUTH、AVOID 按类分组（FACE / BODY / LIGHT / FORMAT）
- **主角图是中性棚拍，不参与与原片帧的色温/饱和比对**（`#606570` 背景会把统计拉偏）；**场景定场图与首帧必须过五项数值比对**
- **单图信息缺口用文字补**：主角图只有正面略侧一个视角，侧脸轮廓与后背结构要写进提示词的「侧面与背面（文字补位）」一句，并在阶段 5 拍背面/大侧面的段落里用文字复述

**每份提示词的固定八段结构**（文件 `03-资产/prompts/<资产>.md`，单张图没有面板，所以没有「面板标签」一段）：

```text
1 画面类型与构图（写清一张完整画面：非拼图/非多格/非并排；景别/机位/留白） / 2 美学参考锚
3 主体（含 DNA 物件、姿势=心理状态）
4 棚拍与光（主角）或 空间与光（场景、首帧） / 5 色卡（嵌入叙述，保留色号）
6 MATERIAL TRUTH / 7 成像与画风（= 风格句原样） / 8 AVOID（按类分组）
## 风格锚
风格句：<01-拆解/style-anchor.md 原样复制>
负向词：<原样复制>
```

三段骨架（内容描述 / 风格句 / 负向词）不变——只是"内容描述"展开成第 1–6 段，风格句落在第 7 段、负向词落在第 8 段。

**参数门（每一张图都要）**：发「出图申请单」，让学员选定**通道（image2image / text2image）+ 模型版本 + 分辨率 + 比例**，并同单报余额与预计消耗。**张数不是选项，恒为 1**（一个资产一张图，不出候选）。比例按图型定：**主角 = `3:4`**（全身不裁头脚）、**场景 = `9:16`**（与成片同比例）、道具 = `1:1`、首帧 = `9:16`。选定后写 `03-资产/image-gate.md`：

```bash
python scripts/gate_check.py --image-gate 03-资产/image-gate.md --batch img_02
```

`gate_check.py` 校验：模型×分辨率组合（3.0/3.1 → 1k/2k；4.x 与 5.0 → 2k/4k；5.0Pro → 1.5k/2k/4k；改图不支持 3.x）、**张数必须为 1**、**图型与比例是否匹配**（场景/首帧必须 9:16、主角给 1:1 时判 ⚠、旧写法「角色sheet/场景9宫格」判 ⚠）、类型是否用了已废弃的「批量/单张补」、重生成前面是否有同一批次或同一图型的记录。

**逐张门（一张过了才出下一张）**，顺序固定：**主角定妆 → 场景定场 → 首帧图 →（道具）**。

| 图 | 必查 |
|---|---|
| 主角定妆（第 1 张，类型=样张） | **结构十项**：一张完整画面（非拼图/多格）/ 全身不裁头脚 / 略侧 15° 脸可辨 / 纯色冷灰 / 单一主光左上 45° 无柔光箱 / 画面无文字 / DNA 物件与磨损对 / 材质有物理特性 / 侧面与背面文字补位已写 / 多角色可区分；外加肉眼四问（画风同族、光比同档、颗粒同量级、没被美化成海报） |
| 场景定场图 | 结构（画里无人、三个空间锚点齐、色卡不跳、无文字）+ 数值五项（基准取原片该场景帧） |
| 首帧图 | 只做数值五项（基准 = 原片同秒帧） |

```bash
python scripts/style_anchor.py --video "01-拆解/frame_001.jpg" \
  --compare "03-资产/first_A.png" --out "03-资产/qc" --qc-only
```

产出 `03-资产/qc/qc-report.md`：色温 Δ±12 / 饱和 Δ±0.06 / 对比 Δ±8 / 亮度 Δ±12 / 锐度比 0.7–1.4 五项容差，超 2 倍记「明显偏」。出现 ❌ 按差值方向改风格句重出（**仍是 1 张**），不许靠多抽几张碰运气。

## 阶段 3 → 阶段 4（资产 → 提示词）

**输入**：`03-资产/` 的 PNG 文件 + 阶段 3 的资产清单表。

视频提示词中参考素材段写法（**放在正文最前**，编号即命令里的传入顺序）：

```
【参考素材】@Image1 = char_主角.png → 锁定外观（脸/发型/服装/体型），不取背景与姿势
@Image2 = scene_办公室.png → 锁定空间结构与色调，不取图中人物
@Image3 = frame_006.jpg → 锁定构图/景别/机位/光线方向，主体长相不取
@Video1 = src_clips/src_01.mp4 → 只参考动作节奏与运镜，不复制其中主体、服装、背景、配色
```

编号全片统一（角色永远 `@Image1`、场景永远 `@Image2`），每段开头重新声明（生成工具无跨段记忆）。段间衔接：上一段段尾状态写进下一段构图要求 + 用 `last_<NN>.jpg` 作为该段 `@ImageN`；需要改绘衔接帧时仍用 `dreamina image2image`（多图**英文逗号**分隔 `--images="a.png,b.png"`，CLI 不可用时回退 ImageGen）。

**阶段 3 与阶段 5 是交错的，不是串行的**：阶段 3 只产出「主角定妆 + 场景定场 + 第 1 段首帧图」，每样一张。第 2 段及以后的首帧依赖上一段实际生成的画面（抽末帧 `last_<NN>.jpg` 接力，或照实际构图改绘），必须等上一段视频通过验收后才做。提前把 N 张首帧一次性做完 = 白花钱 + 接不上。

## 阶段 4 → 阶段 5（提示词 → 视频）

**输入**：`04-提示词/clip_<NN>.md`（严格 yyl-video-prompt 外壳格式）+ `01-拆解/src_clips/src_<NN>.mp4`（动作参考片段，用 `scripts/split-source.sh` 切；**每段传不传、传多长由用户逐段决定**，见阶段 5.0.5）。

提示词正文的来源约定（质量关键）：
- **风格句** ← `01-拆解/style-anchor.md`，落位按 yyl 写法分（A 一镜到底 → 【光影与风格】；B 多分镜 → 「色彩与影调」+「视觉基调」两处，见阶段 1.6 的映射表）。**色调词要逐字出现**，不许自己另写形容词；负向词写进正文末尾禁止项
- **对白** ← `02-脚本/dialogue-map.md` 的「改写台词」列（**不是** `audio.txt` 的原句——原句只是意思基准）；逐句写「秒数 + 谁 + 语气 + 台词」，让模型直接生成音轨。**原句与改写句绝不能同时出现在提示词里**，否则模型两句都念
- **景别/机位/运镜/构图** ← 阶段 1 逐帧拆解表对应镜头段
- **动作时间轴** ← 脚本分段表 + 拆解表的逐秒动作（时间码即动作预算，关键事件写到具体秒，最后一拍留 0.5 秒）
- **外观描述不进正文**：人物长相、毛色、服装由 `@Image1`（角色图）锁定，正文只写"外观以 @Image1 为准"，不重复描述细节（写了会和参考图打架）
- **【参考素材】段必须在正文最前** ← 阶段 3 的素材包顺序（`@Image1` 角色 / `@Image2` 场景 / `@Image3` 道具 / `@ImageN` 构图或上段末帧 / `@Video1` 原片段）；每个 `@` 写"锁什么 + 不取什么"
- **声音** ← 拆解表/转写稿（环境声底 + 逐秒事件音，无 BGM）

生成走即梦 CLI 的**全能参考 `multimodal2video`**（完整规范见 `references/dreamina-cli.md`）。**每段都必须传图并用 `@ImageN` 点名**，纯文生不许产出正式段落；`frames2video`/`image2video` 只在"首帧像素级对齐"时作为例外，且要在 gate-log 注明原因。

素材传入约定：

| 素材 | 传法 | 在提示词里的名字 |
|---|---|---|
| 角色图 | `--image` 第 1 个 | `@Image1` |
| 场景图 | `--image` 第 2 个 | `@Image2` |
| 道具图（可选） | `--image` 第 3 个 | `@Image3` |
| 该段构图参考（`first_X.png` / `last_NN.jpg`） | `--image` 紧随其后 | `@ImageN` |
| 该段原片段（`src_clips/src_NN.mp4`） | `--video` 第 1 个 | `@Video1` |

**`--image` 的出现顺序就是编号顺序，也是提示词的语义**——申请单清单、命令、提示词三处顺序必须逐字一致。

**上传清单是编号的唯一真源**：每段定稿一份 `04-提示词/clip_<NN>.materials.txt`（`@Image1 | 路径 | 锁什么 | 不取什么`，顺序 = 传参顺序 = `@` 编号）。道具位可选，缺了就整行不写、其后编号顺移，所以**先定清单再核提示词**。定稿后必跑：

```bash
python scripts/ref_check.py --materials 04-提示词/clip_NN.materials.txt --duration 6 \
  --style-anchor 01-拆解/style-anchor.md \
  --out 04-提示词/clip_NN.refs.md --emit-cmd 04-提示词/clip_NN.cmd.sh
```

退出码非 0（有 ✘）= **不许发申请单**。通过后命令已生成在 `cmd.sh`，提交时执行它，不要手打——手打必然与提示词编号错位。

字段映射：
- 提示词文件"提示词"代码块内容 → `--prompt`（元信息外壳、段尾状态行不传；走 `$(cat 04-提示词/.prompt/clip_NN.prompt.txt)` 避免转义）
- 每个 `--image` / `--video` → 按上表顺序
- 画幅 → `--ratio`（竖屏 `9:16`；**例外通道** `image2video`/`frames2video` 用 seedance2.5 时禁止传）
- 时间码总时长 → `--duration`（向上取整，4–30s，不超模型上限）
- `--video_resolution` 必填（抖音竖屏默认 720p）
- 提交带 `--poll=120`；超时仍 querying → `query_result --submit_id=<id> --download_dir=05-成片` 跟进下载

**成功判定**：`gen_status=success` 才算完成，不以提交受理为准。

**逐次生成授权契约（硬门）**：本阶段不是一个批次，而是 N 个独立申请，且同一段的第 2 次提交（重生成/重试）也算新的一次申请。每次提交前必须满足六项：

| 条件 | 校验方式 |
|---|---|
| 上传清单已定稿且机械校验通过 | `python scripts/ref_check.py --materials 04-提示词/clip_NN.materials.txt`，**✘ 必须为 0**（它同时验文件存在/编号连续/`@` 集合一致/每个 `@` 有不取项/无致哑表述/两份正文一致） |
| 生成命令来自 `ref_check --emit-cmd` | 执行 `04-提示词/clip_NN.cmd.sh`，不手打 |
| 该段参考图已过风格三问 | 与 `frame_<秒>.jpg` 并排比对，结论写进对话 |
| 该段提示词已过结构校验 | `python vendored/yyl-video-prompt/scripts/prompt_builder.py --validate 04-提示词/clip_NN.md` |
| 该段已获学员授权（**这一次的**） | `05-成片/gate-log.md` 里有对应的「动作 + 上传素材 + 用户授权原话 + 授权时间」行 |
| 台账能对上账 | `python scripts/gate_check.py --gate 05-成片/gate-log.md --segment clip_NN`，**✘ 必须为 0**（它查授权原话是否具体、时间是否倒挂、动作列是否标对、上传素材是否为空） |

`gate-log.md` 结构（每段**每次提交**一行，原话引述，不许概括；表头用 `gate_check.py --template video` 打印）：

| 序号 | 段号 | 动作 | 通道/模型 | 参数 | 参考视频 | 预计积分 | 实际积分 | 上传素材（@ 编号） | 申请时间 | 用户授权原话 | 授权时间 | submit_id | 结果 | 备注 |
|---|---|---|---|---|---|---|---|---|---|---|---|---|---|---|
| 1 | clip_01 | 首次 | multimodal2video / seedance2.5 | 6s/720p/9:16 | 传 src_01（3s） | 约99–117 | 108 | @Image1 char_猫、@Image2 scene_摊、@Image3 frame_001、@Video1 src_01 | 10-28 14:02 | "第1段可以，选A带参考视频" | 10-28 14:05 | 1234567 | success | 原生人声 ✅ |
| 2 | clip_01 | 重生成-画面 | multimodal2video / seedance2.5 | 6s/720p/9:16 | 不传 | 约120 | — | @Image1 char_猫、@Image2 scene_摊、@Image4 last_00 | 10-28 15:10 | "第1段重做一版，这次不带参考视频" | 10-28 15:12 | — | 待提交 | 上版尾帧抖 |

授权粒度：**一段一次**，第 N 段的授权不覆盖第 N+1 段，**第 1 次的授权也不覆盖第 2 次**；"全自动/直接跑完"不豁免；模糊答复（"都行/随便/你看着办"）不算授权。

**实际积分必须回填**：每行生成成功后从 `dreamina list_task` 读 `commerce_info.credit_count` 填进「实际积分」列。`gate_check.py` 对「已生成但没回填」报 ⚠、对「与预计偏差 >30%」也报 ⚠，并汇总出全片实际消耗——这是报价脚本唯一的校准来源（`quote.py --calibrate --ref <秒>`）。

**参考视频逐段决策（硬门，见 SKILL.md 5.0.5）**：`--video` 走的是另一档计费（计费秒数 = 参考片段 + 输出），所以每段都要让用户在 A/B 之间选，并同时给出两档积分与效果差。台账「参考视频」列必填 `传 src_NN（Xs）` 或 `不传`，且要与上传素材里的 `@Video1` 一致；`gate_check.py` 会查这两处矛盾。报价用 `python scripts/quote.py --duration <秒> --resolution <档> --ref <参考秒>`，第一段带参考视频成功后跑 `--calibrate --ref <秒>` 固定实测单价。

**重生成/重试/换通道的契约**（动作列必须写对，否则台账看不出花了两次钱）：

| 触发 | 动作列 | 前置要求 |
|---|---|---|
| 画面不满意 | `重生成-画面` | 先改 `clip_NN.md` → 重跑 `ref_check`（素材/`@` 变动时）→ 重发申请单 |
| 音频验收不过 | `重生成-音频` | 按 5.5.1 排查顺序改声音段 → 重跑 `ref_check` → 重发申请单 |
| 提交 fail / 超时重提 | `重试-失败` | 备注写 `fail_reason` → 重发申请单（重试也扣积分） |
| 换 frames2video / image2video / text2image | `例外通道` | 备注写原因 → 重发申请单，不得沿用上一条授权 |

上一轮结果**必须落账不许删**（fail 写 fail + 原因；画面生成了但不采用写 success + 备注"未采用"），旧产物移到 `05-成片/_old/clip_<NN>_v1.mp4`，避免 `ls clip_*.mp4 | sort` 拼进废弃版本。

## 阶段 5 → 阶段 5.5（生成结果 → 音频验收，兜底时才配音）

**执行顺序：逐段交错，不是批处理。** 每段 `clip_<NN>.mp4` 下载、交付、学员说"通过"之后，**立刻做完该段的 5.5.1 验收，再发下一段的生成申请**。不要把 5.5 攒到所有段生成完再做——攒着做的后果是：前面几段全是哑片，等发现时几百分已花完。

**关键事实（已实测更正）**：即梦的视频命令没有 `--audio` 输出开关，但 **seedance 2.5 输出的 mp4 自带 AAC 音轨**（原生音画同步）。实测 `h264,video` + `aac,audio` 双流，音轨与视频等长、mean −34dB / max −3.6dB、全程无静音。所以**对白写在提示词里由模型直接说**，不是后期配。

**输入**：
- `05-成片/clip_<NN>.mp4`（画面 + **模型原生音轨**）
- `04-提示词/clip_<NN>.md` 的声音段（该段应有哪几句台词、各在第几秒）

**验收（每段必做）**：
```bash
bash scripts/ffx.sh ffprobe -v error -show_entries stream=codec_type,codec_name -of csv=p=0 05-成片/clip_01.mp4   # 期望 h264,video + aac,audio
mkdir -p 05-成片/_qc                                                                          # ffmpeg 不会自动建目录
bash scripts/ffx.sh ffmpeg -y -v error -i 05-成片/clip_01.mp4 -vn -ar 16000 -ac 1 05-成片/_qc/clip_01.wav          # 抽音轨后交给平台转写工具
```
**转写用平台的音频转写能力（秒级）；本地 whisper 跑短音频要几分钟，别用。**

| 结果 | 处理 |
|---|---|
| 台词清楚、时间点对得上 | ✅ 记 `原生人声 ✅`，进下一段 |
| 有人声但念错/被压住 | ⚠️ 改提示词重跑该段（重跑需重新授权） |
| 只有环境声、无台词 | ❌ 删掉提示词里所有"不出声/后期配音"表述，对白块提到声音段最前，确认 `seedance2.5`，拆短台词后重跑 |

**兜底配音（仅当重跑仍无人声）**：
- `05-配音/dialogue_c<NN>.json` —— `voices`（角色↔TTS 音色）+ `lines`（`start`/`text`/`who`/`rate`/`pitch`）
- `05-配音/clip_<NN>_dub.mp4` —— 视频流 `-c copy` 只加 AAC 音轨

**时间码转换规则**：
| 环节 | 时间基准 | 处理 |
|---|---|---|
| 单段配音 | 段内相对秒 | `start = 台词起点 − 0.2`（抵消 TTS 前置静音） |
| 拼接后补配 | 成片绝对秒 | `dub.py --offset <段起点>`，不改 json |
| 校验容差 | — | 有声区间起点与表格偏差 ≤ 0.3s；`max_volume ≤ -3dB` |

**校验命令**：
```bash
bash scripts/ffx.sh ffmpeg -i 05-配音/clip_01_dub.mp4 -af "silencedetect=noise=-35dB:d=0.25" -f null -
bash scripts/ffx.sh ffmpeg -i 05-配音/clip_01_dub.mp4 -af volumedetect -f null -
```

## 阶段 5.5 → 阶段 6（带人声成片 → BGM）

**硬门**：学员确认成片（回看完 clip / 拼接版，明确说"视频 OK"）之前，不得启动 BGM 生成。学员要求改段 → 回阶段 4/5。

**输入**：带人声的成片（默认 `05-成片/成片_无BGM.mp4`；走过兜底配音的段用 `05-配音/成片_配音版.mp4`）；`01-拆解/breakdown.md` 的声音层记录（原片 BGM 风格/情绪/节奏）+ 镜头段级时间轴（卡点秒数）。

**产出**：
- `06-BGM/bgm-spec.md` —— 风格情绪（源自拆解声音层）、时长（=成片总长）、情绪曲线与卡点（对齐钩子/转折/结尾的秒数）、前奏≤2s、结尾淡出 1s、人声共存音量策略（有对白时 BGM -26~-22dB）
- BGM 音频文件（通道回退：即梦 Web AI 音乐 → 学员曲库 → Suno 等第三方；CLI 无音乐命令）
- `06-BGM/成片_BGM版.mp4` —— ffmpeg：BGM 截取/循环到成片时长 + 首尾 1s afade + amix（人声轨为主、BGM 为底），视频流 `-c copy` 只重编码音轨
