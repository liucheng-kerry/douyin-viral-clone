# 阶段衔接契约（pipeline-spec）

各阶段之间的数据接口。上一阶段的产出就是下一阶段的输入，格式对不上就跑不通。

## 阶段 1 → 阶段 2（拆解 → 脚本）

**输入**：`01-拆解/` 下的 `frame-table.md`（逐帧拆解表）+ `breakdown.md`（含镜头段级时间轴拆解表）。

脚本阶段只取四样：
1. 爆款公式中的**段落结构模板**（钩子→铺垫→转折→CTA 的段落划分与每段时长）
2. **镜头段级时间轴**的节奏数据（每段几秒、切点密度、钩子出现秒数）
3. **画面公式**（景别/机位/运镜序列、色调、场景数——逐帧拆解表合并出的镜头段）
4. **逐帧拆解表**中可迁移的构图与道具细节（写脚本"画面内容"列时直接引用）

替换规则：结构照搬、内容全换。逐段对照镜头段级时间轴写新表的"画面内容/口播"两列，时长列保持一致或按新内容微调（±20% 内）。

## 阶段 1 → 阶段 1.6（拆解 → 风格锚）

**输入**：`01-拆解/video/` 下的原片 + `frame_*.jpg`。

```bash
python scripts/style_anchor.py --video "01-拆解/video/<文件>" --out "01-拆解" --frames 12
```

**产出**：
- `01-拆解/style-anchor.md` —— 量化数据表（亮度/对比度/饱和度/色温/锐度/高光暗部/主色相）+ 主色板 Top6 + **风格句** + **负向风格词** + 画风判定表 + 质检三问
- `01-拆解/style-swatch.svg` —— 主色板可视化

**必填空**：脚本只给数值，"画风/镜头质感/光源"三行必须由 agent 用 ViewImage 看帧后补齐，补完可用 `--style-word` 重跑刷新风格句。

**下游契约（硬性）**：阶段 3 每张图片提示词、阶段 4 每段提示词的「视觉基调」行，**必须原样包含风格句**，正文末尾**必须带负向词**。四个文件里的风格句要逐字一致。

## 阶段 2 → 阶段 3（脚本 → 图片资产）

**输入**：`02-脚本/script.md` 的分段时间轴表。

从表中提取资产清单：
- **角色**：每段出现的主体人物。同一角色全片只用一张 character sheet，跨段锁定一致性。
- **场景**：发生地点变化处建场景图。同场景多段共用。
- **关键道具/首帧**：表里"画面内容"列提到的特写物、开场画面。

资产清单先列成表（资产名 | 类型 | 出现段号 | 锁定要素）再逐个写提示词。提示词正文要能直接回答该资产在视频提示词中"锁定什么、不用什么"。

**每份提示词的固定三段结构**：

```text
<内容描述：主体/姿态/道具/环境/景别/机位/构图/光线方向>
<风格句：01-拆解/style-anchor.md 原样复制>
避免：<负向风格词：原样复制>
```

**样张门**：先只生成第 1 段首帧图作为样张，与 `01-拆解/frame_<该段起始秒>.jpg` 并排做风格三问（色调/质感/光线），并跑数字对照：

```bash
python scripts/style_anchor.py --video "01-拆解/frame_001.jpg" \
  --compare "03-资产/first_A.png" --out "03-资产/qc" --qc-only
```

产出 `03-资产/qc/qc-report.md`：色温 Δ±12 / 饱和 Δ±0.06 / 对比 Δ±8 / 亮度 Δ±12 / 锐度比 0.7–1.4 五项容差，超 2 倍记「明显偏」。全 ✅ 且学员点头后，才批量生成剩余资产；出现 ❌ 按差值方向改风格句重出样张，不许靠多抽几张碰运气。

## 阶段 3 → 阶段 4（资产 → 提示词）

**输入**：`03-资产/` 的 PNG 文件 + 阶段 3 的资产清单表。

视频提示词中参考素材段写法：

```
参考素材：
图片1：@char_主角.png——锁定 [脸部/发型/服装]；不使用 [背景/图中姿势]
图片2：@scene_办公室.png——锁定 [空间结构/色调]；不使用 [图中人物]
```

编号全片统一，每段开头重新声明（生成工具无跨段记忆）。段间衔接：上一段段尾状态写进下一段首帧要求；需要衔接帧时用 `dreamina image2image` 以"把图片1改为……状态"的方式从上段首帧改绘（多图用**英文逗号**分隔 `--images="a.png,b.png"`，CLI 不可用时回退 ImageGen）。

## 阶段 4 → 阶段 5（提示词 → 视频）

**输入**：`04-提示词/clip_<NN>.md`（严格 yyl-video-prompt 外壳格式）。

提示词正文的来源约定（质量关键）：
- **`视觉基调：` 行** ← `01-拆解/style-anchor.md` 的风格句（**各段逐字相同**，不许自己另写形容词），负向词写进正文末尾禁止项
- **对白** ← `01-拆解/audio.txt` 的原片转写稿（原样搬用，不重写不翻译），逐句写「秒数 + 谁 + 语气 + 台词」，让模型直接生成音轨
- **景别/机位/运镜/构图** ← 阶段 1 逐帧拆解表对应镜头段
- **动作时间轴** ← 脚本分段表 + 拆解表的逐秒动作（时间码即动作预算，关键事件写到具体秒，最后一拍留 0.5 秒）
- **外观描述不进正文**：首帧图生模式下人物长相、毛色、服装全部由 `--image` 首帧图锁定，正文不重复描述
- **声音** ← 拆解表/转写稿（环境声底 + 逐秒事件音，无 BGM）

生成走即梦 CLI（完整规范见 `references/dreamina-cli.md`），按每段标注的**生成模式**映射命令：

| 生成模式 | Dreamina 命令 | 素材传入方式 |
|---|---|---|
| 纯文生 | `text2video` | 无图，仅 `--prompt` |
| 首帧图生 | `image2video` | 该段首帧图 → `--image` |
| 首尾帧 | `frames2video` | 本段起始帧 + 下一段首帧（尾帧） |
| 多图参考 | `multiframe2video` | 本段引用的参考图列表 |
| 全能参考 | `multimodal2video` | 图/视频/音参考（Seedance 2.5 多图时用） |

字段映射：
- 提示词文件"提示词"代码块内容 → `--prompt`（元信息外壳、段尾状态行不传）
- 该段首帧图 → `--image`（首帧图生模式）
- 画幅 → `--ratio`（"9:16"/"16:9"；`image2video`/`frames2video` 用 seedance2.5 时**禁止传**，输出跟随首帧）
- 时间码总时长 → `--duration`（向上取整，不超模型上限）
- `--video_resolution` 必填（抖音竖屏默认 720p）
- 提交带 `--poll=120`；超时仍 querying → `query_result --submit_id=<id> --download_dir=05-成片` 跟进下载

**成功判定**：`gen_status=success` 才算完成，不以提交受理为准。

**逐段授权契约（硬门）**：本阶段不是一个批次，而是 N 个独立申请。每段提交前必须满足三项：

| 条件 | 校验方式 |
|---|---|
| 该段首帧图已过风格三问 | 与 `frame_<秒>.jpg` 并排比对，结论写进对话 |
| 该段提示词已过结构校验 | `python vendored/yyl-video-prompt/scripts/prompt_builder.py --validate 04-提示词/clip_NN.md` |
| 该段已获学员授权 | `05-成片/gate-log.md` 里有对应的「用户授权原话 + 授权时间」行 |

`gate-log.md` 结构（每段一行，原话引述，不许概括）：

| 段号 | 申请时间 | 段长/模式/预计积分 | 用户授权原话 | 授权时间 | submit_id | 结果 |
|---|---|---|---|---|---|---|
| clip_01 | 10-28 14:02 | 6s/首帧图生/约120 | "第一段可以生成" | 10-28 14:05 | 1234567 | success |

授权粒度：一段一授权，第 N 段的授权不覆盖第 N+1 段；"全自动/直接跑完"不豁免；模糊答复（"都行/随便"）不算授权。失败重试同样要重新报费用并取得同意。

## 阶段 5 → 阶段 5.5（生成结果 → 音频验收，兜底时才配音）

**关键事实（已实测更正）**：即梦的视频命令没有 `--audio` 输出开关，但 **seedance 2.5 输出的 mp4 自带 AAC 音轨**（原生音画同步）。实测 `h264,video` + `aac,audio` 双流，音轨与视频等长、mean −34dB / max −3.6dB、全程无静音。所以**对白写在提示词里由模型直接说**，不是后期配。

**输入**：
- `05-成片/clip_<NN>.mp4`（画面 + **模型原生音轨**）
- `04-提示词/clip_<NN>.md` 的声音段（该段应有哪几句台词、各在第几秒）

**验收（每段必做）**：
```bash
ffprobe -v error -show_entries stream=codec_type,codec_name -of csv=p=0 05-成片/clip_01.mp4   # 期望 h264,video + aac,audio
ffmpeg -y -v error -i 05-成片/clip_01.mp4 -vn -ar 16000 -ac 1 05-成片/_qc/clip_01.wav          # 抽音轨后交给平台转写工具
```
**转写用平台的音频转写能力（秒级）；本地 whisper 跑短音频要几分钟，别用。**

| 结果 | 处理 |
|---|---|
| 台词清楚、时间点对得上 | ✅ 记 `原生人声 ✅`，进下一段 |
| 有人声但念错/被压住 | ⚠️ 改提示词重跑该段（重跑需重新授权） |
| 只有环境声、无台词 | ❌ 删掉提示词里所有"不出声/后期配音"表述，对白块提到声音段最前，确认 `seedance2.5`，拆短台词后重跑 |

**兜底配音（仅当重跑仍无人声）**：
- `05-配音/dialogue_c<NN>.json` —— `voices`（角色↔TTS 音色）+ `lines`（`start`/`text`/`who`/`rate`/`pitch`）
- `05-配音/clip_<NN>_dub.mp4` —— 视频流 `-c copy` 只加 AAC 音轨

**时间码转换规则**：
| 环节 | 时间基准 | 处理 |
|---|---|---|
| 单段配音 | 段内相对秒 | `start = 台词起点 − 0.2`（抵消 TTS 前置静音） |
| 拼接后补配 | 成片绝对秒 | `dub.py --offset <段起点>`，不改 json |
| 校验容差 | — | 有声区间起点与表格偏差 ≤ 0.3s；`max_volume ≤ -3dB` |

**校验命令**：
```bash
ffmpeg -i 05-配音/clip_01_dub.mp4 -af "silencedetect=noise=-35dB:d=0.25" -f null -
ffmpeg -i 05-配音/clip_01_dub.mp4 -af volumedetect -f null -
```

## 阶段 5.5 → 阶段 6（带人声成片 → BGM）

**硬门**：学员确认成片（回看完 clip / 拼接版，明确说"视频 OK"）之前，不得启动 BGM 生成。学员要求改段 → 回阶段 4/5。

**输入**：带人声的成片（默认 `05-成片/clip_<NN>.mp4` 拼接版；走过兜底配音的段用 `05-配音/clip_<NN>_dub.mp4`）；`01-拆解/breakdown.md` 的声音层记录（原片 BGM 风格/情绪/节奏）+ 镜头段级时间轴（卡点秒数）。

**产出**：
- `06-BGM/bgm-spec.md` —— 风格情绪（源自拆解声音层）、时长（=成片总长）、情绪曲线与卡点（对齐钩子/转折/结尾的秒数）、前奏≤2s、结尾淡出 1s、人声共存音量策略（有对白时 BGM -26~-22dB）
- BGM 音频文件（通道回退：即梦 Web AI 音乐 → 学员曲库 → Suno 等第三方；CLI 无音乐命令）
- `06-BGM/成片_BGM版.mp4` —— ffmpeg：BGM 截取/循环到成片时长 + 首尾 1s afade + amix（人声轨为主、BGM 为底），视频流 `-c copy` 只重编码音轨

| 拆解报告 | `01-拆解/breakdown.md`（含镜头段级时间轴拆解表） |
| 风格锚 | `01-拆解/style-anchor.md` + `01-拆解/style-swatch.svg` |
| 脚本 | `02-脚本/script.md`（含台词时间码表） |
| 角色图 | `03-资产/char_<角色名>.png` + `03-资产/prompts/char_<角色名>.md` |
