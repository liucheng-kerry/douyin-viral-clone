# Dreamina CLI 生图生视频通道（references）

本工作流阶段 3（图片资产）和阶段 5（视频生成）的执行通道是即梦官方 CLI `dreamina`，让学员全程在 WorkBuddy 内完成，不需要自己去即梦网页版或其他平台。

## 前置检查（每次开工先跑）

```bash
dreamina --version        # 确认 CLI 可用（安装于 ~/bin/dreamina.exe）
dreamina user_credit      # 确认登录态 + 报积分余额 + 看 vip_level
```

> 三件事一起做完再开工：**登录态**（`--headless` 两段式，见下）、**余额**（不够就在阶段 0 说，别等阶段 5）、**`vip_level`**（`seedance2.5` 标注 VIP 限定）。脚本 `scripts/check-env.sh` 已把这三项都打出来了，先跑它。

- 已登录 → 直接向用户报「当前余额 N 积分」。
- **顺手确认 VIP 等级**：`user_credit` 返回的 `vip_level`（本机示例 `standard`）。CLI 帮助写明默认通道 `multimodal2video` + `seedance2.5` 是 **VIP 限定**；`standard` 账号是否真被拦截尚未实测，所以**按可能被拒处理**——提前说明，提交报权限不足就降级 `seedance2.0_vip`（720p/1080p/4k，图 ≤9）或让学员开会员，不要闷头提交等报错。
- **首次用某个模型要先在网页端跑一次**：CLI 帮助原文「部分模型首次使用时，需要先在即梦 Web 端使用该模型完成首次生成」，否则提交返回 `AigcComplianceConfirmationRequired`。第一次用 seedance2.5 前先跟学员打招呼，别等报错。
- 未登录/报错 → 走 **headless 两段式**，不要直接跑 `dreamina login`：它打印链接后会一直阻塞等授权，学员在浏览器里花几分钟，命令早就超时、链接也贴不出去。

  ```bash
  dreamina login --headless                                  # 打印 verification_uri / user_code / device_code 后立即退出
  dreamina login checklogin --device_code=<code> --poll=30    # 学员授权后确认（--poll=0 只查一次）
  ```

  把 `verification_uri` 与 `user_code` **原样**贴给学员，说清「几分钟内有效 / 打开后核对用户码一致 / 完成后回我一声」。已登录时 `--headless` 会直接回「已复用当前本地 OAuth 登录态」，所以这条命令可以安全重复跑。换账号或 token 失效（`user_credit` 报未登录 / 401）→ `dreamina relogin --headless` 重走一遍。成功后把 user_id / vip_level / total_credit 明确告知学员，**不能只贴链接就走**。
- CLI 不可用且学员不便授权（网络故障、无即梦账号）→ 回退 WorkBuddy 内置 ImageGen/VideoGen，并明确告知通道变更（此时 **`@` 引用机制失效**，只能靠文字描述，质量会降一档，要如实说）。

## 授权与费用（硬门槛，不可跳过、不可合并授权）

所有真实生成任务执行前：

1. 跑 `dreamina user_credit` 报当前余额；
2. **报参数**：出图 = 通道 / 模型版本 / 分辨率 / 比例 / 张数；视频 = 模型 / 时长 / 分辨率 / 比例 —— 这些**由学员选定或确认**，不许用默认值直接跑；
3. 估算本次消耗——**按实测单价算，不凭印象**：`python scripts/quote.py --duration <秒> --resolution <档> --ref <参考片段秒>`；本机实测图片 5.0/2k = 3 积分、5.0Pro/2k = 8 积分，视频 seedance2.5 480p = 12 积分/秒、720p = 20 积分/秒（输出秒）；
4. 记账（图片 `03-资产/image-gate.md`、视频 `05-成片/gate-log.md`）并跑 `python scripts/gate_check.py` 过关；
5. 等学员点名确认后再执行。

**两条线的授权粒度不同，但"每次生成都要授权"这条相同**：

| 阶段 | 授权粒度 | 说明 |
|---|---|---|
| 阶段 3 生图 | **一张图一次授权** | **每段提示词只出一张图**（主角=单张定妆照、场景=单张定场图、每段=一张首帧），张数恒为 1；每张图先发「出图申请单」让学员选定**通道/模型版本/分辨率/比例**（不许拿默认值直接跑），出完即检，过了才出下一张；重出仍是 1 张、仍要重新授权 |
| 阶段 5 生视频 | **一段一次授权** | 每段每次提交都单独发「生成申请单」，学员逐段点名确认；第 N 段不覆盖第 N+1 段，第 1 次不覆盖第 2 次 |

**重生成/重试/换参数/换通道 = 一次新的生成，一律重发申请单**，不许沿用上一次的授权：

| 情况 | 申请单要写 | 台账动作列 |
|---|---|---|
| 图片样张没过、批量里有几张不合格、想换模型再试 | 第 N 次 + 上次为什么不行 + 新参数 | 类型=`重生成`（`03-资产/image-gate.md`） |
| 视频画面不满意 | 上次哪里不行 + 这次改了什么 | `重生成-画面` |
| 视频音频验收不过（没台词/念错） | 上次转写到的实际人声情况 | `重生成-音频` |
| 提交 fail / 超时 / 合规拦截后重提 | `fail_reason` 原文 | `重试-失败` |
| 换 `frames2video`/`image2video`/`text2image` 等通道 | 为什么换 + 费用差多少 | `例外通道` + 备注原因 |

两个台账（图片 `03-资产/image-gate.md`、视频 `05-成片/gate-log.md`）由 `scripts/gate_check.py` 校验，**✘ 未清零不许执行任何 `dreamina` 生成命令**——详见 SKILL.md《生成授权总纲》与阶段 3.4 / 5.1。

视频段的授权必须落到 `05-成片/gate-log.md`（动作 / 参考视频 / 参数 / 预计积分 / 实际积分 / 上传素材 / 用户原话 / 授权时间 / submit_id / 结果），**没有这一行不许提交**。申请单的九项固定内容（含「本次是第 K 次」、「上传清单」与**参考视频 A/B 两档报价**）见 SKILL.md 阶段 5.2；上传清单本体在 `04-提示词/clip_<NN>.materials.txt`，由 `scripts/ref_check.py` 校验并生成命令。

**生成成功立刻回填「实际积分」**：`dreamina list_task` 里该任务的 `commerce_info.credit_count` 就是真实扣费。只填「预计积分」等于自己给自己报价、从不验收——`gate_check.py` 会报 ⚠，偏差超 30% 时提示用 `quote.py --calibrate` 重校单价。

## 计费：传不传参考视频是两档（`--video` 逐段可选）

每次生成都会在任务记录里留下 `commerce_info.credit_count`（真实扣了多少）和 `benefit_type`（走了哪个计费 SKU）。SKU 名里带 `no_input_video` ——**说明"有输入视频"是另一档价格**，所以 `--video` 不是"多传一个素材而已"，它换档。

**本机实测（seedance2.5，`no_input_video` 档）**：

| 项 | 单价 | 说明 |
|---|---|---|
| 视频 480p | **12 积分/秒** | 按输出秒数计（3 条样本一致） |
| 视频 720p | **20 积分/秒** | 按输出秒数计（4 条样本一致） |
| 视频 1080p | 暂无实测 | 需要时先跑一段小样测价，别猜 |
| 图片 5.0 / 2k | **3 积分/张** | 5 条样本 |
| 图片 5.0Pro / 2k | **8 积分/张** | 2 条样本 |

**两档公式**：

| | 公式 | 例（6s 输出 / 720p） |
|---|---|---|
| 不传参考视频 | 单价 × 输出时长 | 6 × 20 = **120 积分** |
| 传参考视频 | 输入视频档单价 ×（**参考片段秒数 + 输出秒数**） | 12 秒 × 11–13 ≈ **132–156 积分** |

- 输入视频档单价低于无视频档（约 0.55–0.65 倍），但**计费秒数把参考片段也算进去**，所以总价不一定更低：按系数 0.65 算，**参考片段 ≤ 输出时长的 0.54 倍**时才不比不传贵（系数 0.55 时可放宽到 0.82 倍）；与输出等长时贵 10–30%；整段传会明显更贵。平衡点一律用 `scripts/quote.py` 按本机实测单价算，别手算。
- **该档单价必须实测一次**：第一段带参考视频的生成成功后立刻反推，之后所有报价用实测值（SKILL.md 5.0.5 有完整流程）。

**报价命令（别凭印象报数）**：

```bash
python scripts/quote.py --duration 6 --resolution 720p --ref 3   # A/B 两档 + 平衡点
python scripts/quote.py --rate-only                              # 只要实测单价表
python scripts/quote.py --calibrate --ref 3                      # 用带视频的真实扣费反推单价
```

## 命令速查（详细参数以 `dreamina <子命令> -h` 为准，不要凭记忆硬编码）

### 改图 image2image（★ 风格一致的首选通道）

```bash
# 帧名换算：frame_001 = 第 0 秒，frame_002 = 第 1 秒……即 frame_(起始秒 + 1)
dreamina image2image --images="01-拆解/frame_001.jpg,03-资产/char_主角.png" \
  --prompt="保留图1的构图/景别/机位/光线/色调与背景，只把主体替换为图2的角色，姿态与占位不变，其余一切不变。<风格句> 避免：<负向词>" \
  --ratio=9:16 --resolution_type=2k --generate_num=1 --poll=60
```

- `--images strings` 支持 1–10 张本地图片（超过 10 张易失败）。**多图必须用英文逗号分隔（`--images="a.png,b.png"`）**——用空格分隔会被当成多余位置参数直接报 `unknown command`（已实测）；路径里不要带逗号。
- `--ratio` 省略则默认 16:9；`--resolution_type` 必填；**模型 4.0 起才支持改图**（3.x 会报错），4.0–5.0 → 2k/4k，5.0Pro → 1.5k/2k/4k。
- **模型/分辨率/比例由学员在阶段 3.4 的出图申请单里定**，不要拿默认值直接跑；**张数恒为 1**（`--generate_num=1`，本技能不出候选）；`gate_check.py` 会按 CLI 实测矩阵校验这些组合，并挡「张数 >1」「场景/首帧用了 1:1」。
- **为什么首选它做首帧**：原片帧提供构图、光线、色调、景深，风格天然同族，比纯文生稳定得多。
- **为什么仍要带风格句**：模型会重绘，句子里不锁风格它就会自行"美化"成商业大片质感。
- **prompt 禁忌**：不要重复描述外观（长相/毛色/服装由角色图锁定），否则和参考图打架。
- 用途：各段首帧图、衔接帧改绘、主角替换微调。**重出（换提示词/换模型再试）同样要重发申请单**。

### 生图 text2image（无原片帧对应时用）

```bash
# 主角定妆照：3:4 竖构图，全身入画不裁头脚
dreamina text2image --prompt="..." --ratio=3:4 --resolution_type=2k --generate_num=1 --model_version=5.0 --poll=60
# 场景定场图：9:16 与成片同比例
dreamina text2image --prompt="..." --ratio=9:16 --resolution_type=2k --generate_num=1 --model_version=5.0 --poll=60
```

- `--resolution_type` **必填**；`--ratio` 支持 21:9/16:9/3:2/4:3/1:1/3:4/2:3/9:16（默认 16:9），可与 `--width/--height` 互换（两者必须成对、互斥）。
- 模型与分辨率组合（**选错组合 CLI 直接拒绝**）：3.0/3.1 → 1k/2k；4.0/4.1/4.5/4.6/4.7/5.0 → 2k/4k；5.0Pro → 1.5k/2k/4k。默认模型 5.0。
- `--generate_num` 支持 1–10，但**本技能恒用 1**：一段提示词只出一张图，不出候选、不出多面板多角度。`--poll=N` 提交后顺带等 N 秒。
- **比例按图型定**：主角 → `3:4`（方图/横图会切腿）；场景定场图与首帧图 → 与成片同比例（`9:16`，横屏 16:9）；道具特写 → `1:1`。
- **模型/分辨率/比例必须先让学员在 3.4 申请单里选定**；要多个资产 = 多次申请、每次一张、每张各自授权。

### 生视频：全能参考 `multimodal2video`（★ 默认且唯一的正式通道）

对应即梦 Web 的「全能参考」（旧名 ref2video）。**所有正式段落都走这条**，其余命令只在标明例外时用。能力边界以 `dreamina multimodal2video --help` 实测为准：

| 项 | seedance2.5 | seedance2.0 家族 |
|---|---|---|
| 图片上限 | ≤30 张 | ≤9 张 |
| 视频上限 | ≤10 条，单条 2–30s，**总长 ≤30s** | ≤3 条，总 ≤15s |
| 音频上限 | ≤10 条，单条 2–30s，总 ≤30s | ≤3 条 |
| 素材总数 | ≤50 | ≤12 |
| 输出时长 | 4–30s | 4–15s |
| 分辨率 | 480p / 720p / 1080p | 720p（`_vip` 可 720p/1080p/4k） |
| 权限 | **VIP 限定** | 普通可用 |
| 最少素材 | 可以只传音频 | 至少 1 图或 1 视频 |

**`@` 引用机制（这条不写对，多图就是白传）**

上传后在 prompt 里用 `@Image1` / `@Video1` / `@Audio1` 逐个点名，编号规则：

- `--image` 按**命令行出现顺序**编号：第 1 个是 `@Image1`，第 2 个 `@Image2`……
- `--video` 独立编号，从 `@Video1` 起；`--audio` 从 `@Audio1` 起（不要混入 Image 序号）
- **调换 `--image` 顺序 = 改变提示词语义**。申请单里的清单顺序必须与命令逐字一致

官方（Seedance 2.5 发布会 30 秒音乐会示例）的写法结构值得照搬：**先给画幅/影调 → 再逐个分配每个素材的职责（"Use @Image1 for the venue"）→ 最后才写动作与镜头**。职责在前、动作在后，模型才分得清哪张图管什么。

**`@` 是否真被解析，第一次生成后必须验证**

提交第 1 段后先看输出：如果主体明显不像 `@Image1` 的角色、或背景被 `@Video1` 整段抄走，说明这次提交没吃到引用分工。按这个顺序试，一次只改一处：

1. 把 `@Image1` 换成自然语言指代（"图1中的人物""第一张图里的猫"）再提交一次——自然语言指代同样有效，某些版本对它更敏感
2. 两者都无效 → 该 CLI 版本可能不透传引用标记：此时改用"**减少素材 + 强化文字**"（只传角色图 + 场景图，其余靠描述），并在交付说明里如实告诉学员这个局限，不要假装分工生效了
3. 别靠加图解决——图越多，没被点名的图越容易变成噪音

**素材职责：一个素材只给一件事**

| 传入 | 交给它 | 不要它管 |
|---|---|---|
| `--image` 角色图 | 脸、毛色/发色、体型、服装、材质 | 背景、姿势、构图 |
| `--image` 场景图 | 地点、陈设、空间结构、招牌文字 | 人物、光比强度 |
| `--image` 道具图 | 外形、状态、标签文字 | 场景、人物 |
| `--image` 原片同秒帧 | 构图、景别、机位、光线方向 | 主体长相 |
| `--image` 上段末帧 | **`画面首帧`**：本段第一帧的构图、景别、机位、主体位置、光线方向（只用于续接段） | 上一段的动作残余、表情走向；切镜段不传 |
| `--video` 原片段 | 动作、运镜、节奏、切点 | **主体形象、服装、背景、配色** |

分工能降低串味概率，但**不保证零串味**——官方文档也明确"separate roles reduce conflicts but do not guarantee that no detail transfers"。所以提示词里必须逐条写"不取什么"。

**串味排查顺序**（出现"角色被带跑/背景被抄"时，按这个顺序一次只改一处）：

1. 该素材的"不取什么"是否写清楚了 → 补一句负面约束
2. 图是不是给多了 → 一次减一张，找出打架的那张（通常是最相似的两张，比如两张都是人物图）
3. 场景图和角色图里是否混进了对方的内容（角色图背景有店招 = 会被当环境）
4. `--video` 传了原片段又传了原片同秒帧 → 两者信息重叠，删掉同秒帧
5. 仍不行 → 拆成两段生成，别在一段里堆素材

**命令（不要手打，用生成出来的）**

```bash
dreamina multimodal2video \
  --image "03-资产/char_猫.png" \
  --image "03-资产/scene_烤鱼摊.png" \
  --image "01-拆解/frame_001.jpg" \
  --video "01-拆解/src_clips/src_01.mp4" \
  --prompt "$(cat "04-提示词/.prompt/clip_01.prompt.txt")" \
  --model_version=seedance2.5 --duration=6 --ratio=9:16 \
  --video_resolution=720p --poll=120
```

上面这条是**样例形态**。实际提交时由 `scripts/ref_check.py --emit-cmd` 生成 `04-提示词/clip_<NN>.cmd.sh`，直接 `bash` 它：脚本会按 `materials.txt` 的顺序拼参数，同时校验提示词里的 `@ImageN` 与本条命令的 `--image` 顺序是否一致。手打最容易犯的错就是把 `--image` 顺序写反——那等于把场景图当角色图用，而 `@` 编号还写着原来的意思。

- `--video_resolution` **必填**；`--ratio` 省略默认 16:9，抖音竖屏显式写 `9:16`
- **模型 / 时长 / 分辨率 / 比例这四项要在阶段 5.2 的申请单里让学员看到并确认**（VIP 判定、480p/720p/1080p 的费用差一并说明），不要闷头用 seedance2.5 + 720p
- `--prompt` 可以传空（纯素材驱动）但**本技能从不这么用**——没有文字就没有台词、没有动作时间轴
- 提示词走文件 + `$(cat …)`，避免命令行转义把 `@` 和引号吃掉；Windows 命令行上限约 8000 字符，正文控制在 1500 字内
- 本地文件会在提交前自动上传，无需手动先传

**例外通道（用了必须在 gate-log 写原因 + 单独授权）**

| 场景 | 命令 | 说明 |
|---|---|---|
| 首帧必须像素级等于参考图 | `frames2video`（首尾帧）或 `image2video` | 全能参考只保证"像"，不保证首帧一致 |
| 仅试风格、不出正式段 | `text2video` | 不许作为段落产物 |
| 多图故事板（固定节奏转场） | `multiframe2video` | 模型不可选；`--images` 逗号分隔 |

```bash
# 首帧图生（例外）：seedance2.5 下禁止传 --ratio，画幅跟随首帧
dreamina image2video --image=./first_A.png --prompt="..." --video_resolution=720p --poll=120
```

- `image2video` / `frames2video` 用 seedance2.5 时**禁止传 `--ratio`**；其他模型可传也可自动跟随
- 各命令 `--duration` 默认 5s

### 音频（重要事实，别再搞错）

所有视频命令（`image2video` / `text2video` / `frames2video` / `multiframe2video` / `multimodal2video`）**没有** `--audio` 之类的"输出音频开关"，但**输出的 mp4 自带 AAC 音轨**——seedance 2.5 是原生音画同步模型，声音是模型生成的：

```bash
bash scripts/ffx.sh ffprobe -v error -show_entries stream=codec_type,codec_name -of csv=p=0 clip_01.mp4
# h264,video
# aac,audio      ← 音轨一直都在（实测 4–8s 段：mean −34dB / max −3.6dB / 全程无静音）
```

- 对白靠**提示词驱动**：写清「第几秒 + 谁 + 语气 + 台词原文」，并要求"直接生成同步人声、口型与音节逐帧对齐"
- **绝不能写**"不生成语音 / 模型不负责出声 / 台词后期配音"——模型会严格执行，结果只有环境声、没有台词（v2 实测：四段音轨都在，台词一句没有）
- `multimodal2video --audio` 是**输入**参考音频（音色/配乐参考），**不是**输出开关，别搞混
- 台词没出来时的排查顺序：① 删掉所有负面表述 → ② 对白块挪到【声音】段最前 → ③ 换 `--model_version=seedance2.5` → ④ 台词拆短（>12 字拆两句）→ ⑤ 去掉 BGM 相关描述

### 查询与下载

```bash
dreamina query_result --submit_id=<id> --download_dir=replicate/<项目>/05-成片
dreamina list_task --gen_status=success
```

## 结果判定与容错（来自 dreamina 官方 SKILL 规范）

- 提交返回 `submit_id` + `gen_status=querying` 只代表**受理成功**，不等于生成成功。
- 只有 `gen_status=success` 才算完成；`fail` 时把 `fail_reason` 原样告知学员并给下一步建议。
- `AigcComplianceConfirmationRequired` → 该模型需先在即梦 Web 端完成一次首次生成确认；引导学员去网页端跑一次再回来重试（这是全流程唯一需要出 WorkBuddy 的例外，要明确说明）。
- 失败段重试 1 次，仍失败则记录原因继续下一段，最后统一汇报。
- `--poll=N` 超时仍 querying → 保存 submit_id，改用 `query_result` 持续跟进。

## 产物落盘与质检

- `--download_dir` 直接指向对应阶段目录；下载后重命名为约定名（`char_<角色名>.png` / `clip_<NN>.mp4`，见 pipeline-spec.md）。
- 图片生成后用 ViewImage 逐张质检：**先看风格三问**（色调/质感/光线 vs 原片同秒帧），再看结构与一致性（一张图 / 全身不裁 / 棚拍光位 / 无文字）；风格不对优先改风格句与负向词，不是多抽几张。
- 视频每段生成完单独交付给学员验收，通过后才进下一段（见阶段 5.3）。
- 每个 `submit_id` 和最终状态记录到项目 `05-成片/README.md`（命令、参数、submit_id、状态），授权信息记 `05-成片/gate-log.md`，两处都要有，便于对账和排查。
