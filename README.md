# douyin-viral-clone —— 一键复刻抖音爆款 AI 视频工作流

把一条对标爆款链接变成自己的 AI 视频成片，**全程在 WorkBuddy 内完成**，不需要学员拿着提示词去即梦或其他平台。

```
对标链接 → ①拆解 → ①.6风格锚定 → ②复刻确认+脚本
        → ③资产（一张一张出：主角定妆 → 场景定场 → 第1段首帧；每段提示词只出一张；每张先申请参数）
        → ④视频提示词（含对白）
        → ⑤逐段生成（每段：首帧 → 选传/不传参考视频（A/B 两档报价）→ 申请授权 → 台账校验
                        → 生成 → 画面验收 → 抽末帧 → 下一段首帧；不满意重跑 = 重新申请授权）
        → ⑤.5音频验收（随段走）→ ⑥BGM
```

## 工作流（阶段 0 + 八个执行阶段）

| 阶段 | 内容 | 关键产出 |
|---|---|---|
| ⓪ 环境自检 | 开工先跑 `scripts/check-env.sh`，缺依赖直接给安装命令，不许闷头往下跑 | 依赖清单 |
| ① 对标拆解 | 以 `yyl-benchmark-breakdown` 为方法论权威（四层+视觉七维），叠加**逐帧九项拆解**（主体/道具/环境/景别/机位/运镜/构图/光线/文字），逐帧合并成镜头段 | `frame-table.md` + 三件套报告 + 声音层记录 |
| **①.6 风格锚定** | 抽帧统计原片的亮度/对比度/饱和度/色温/主色板/锐度 → 生成**风格句 + 负向词**，把"像不像"变成可执行数据；画风定性由 agent 看图补齐；带 `--compare` 还能出**五项差值的质检报告**（色温/饱和/对比/亮度/锐度） | `style-anchor.md` + `style-swatch.svg` |
| ② 复刻确认+脚本 | 确认复刻方式（1:1 / 主角替换 / 只借结构）→ 写分段时间轴脚本 + **台词可重写但语义对照原片**（`dialogue-map.md` 逐句列出原句/改写句/改了什么/判定，`dialogue_check.py` 校验句数·字数·时码） | `script.md` + `dialogue-map.md` |
| ③ 图片资产 | **每段提示词只出一张图**：主角 = 单张定妆照（全身正面略侧 15°，脸与服装结构同时可读；纯色冷灰棚拍、单一主光左上 45°、画面无文字）、场景 = 单张定场图（最常复用的机位，画里不放人）、道具 = 单件特写、首帧 = 每段一张改绘（9:16）——**提示词按 `ai-drama-reference-art` 的写法写**（影视参考锚定、姿势=心理状态、DNA 物件、色卡融入叙述、MATERIAL TRUTH、AVOID 按类分组），但**不要它的面板数**：不出候选、不出多面板多角度。**每张出图前先让用户选定通道 + 模型/分辨率/比例，张数恒为 1**；**一张出完即检，过了才出下一张**（主角走结构十项、场景与首帧另加五项数值），**重出仍是一张、仍要重新申请**。单图丢掉的角度信息**用文字补**（提示词里的「侧面与背面」一句 + 阶段 5 拍背面时复述）。后续段的首帧**不提前做**——等上一段视频通过后抽末帧接力，或照实际构图改绘（阶段③与⑤是交错的） | `char_*.png` / `scene_*.png` / `prop_*.png` / `first_A.png` / `last_<NN>.jpg` + `prompts/*.md` + `image-gate.md` |
| ④ 视频提示词 | 严格按 `yyl-video-prompt` 方法论：**风格句按写法落位**（一镜到底 → 【光影与风格】；多分镜 → 「色彩与影调」+「视觉基调」两处，色调词逐字写）；景别/机位/运镜/构图照逐帧拆解表复刻；正文开头写**【参考素材】段**（每个 `@ImageN` 锁什么、不取什么）；外观交给参考图不重复描述；时间码即动作预算；**对白逐句写进提示词（秒数+谁+语气+台词），让模型直接生成人声音轨** | `clip_<NN>.md` + `.prompt/clip_<NN>.prompt.txt` |
| ⑤ 即梦生成画面 | **全能参考（`multimodal2video`）为默认通道：每段都上传 4–6 张参考图 + 1 条原片段，提示词里用 `@Image1`/`@Video1` 逐个点名分工**。**五段式硬门**：① 写 `clip_<NN>.materials.txt` 上传清单（顺序=编号=传参顺序）→ ② 跑 `scripts/ref_check.py`，**✘ 未清零不许发申请单**，通过后它直接吐出命令 → ③ **逐段选「传 / 不传参考视频」**：`--video` 走另一档计费，两档积分与效果差都要摆给用户（`scripts/quote.py` 按实测单价算），台账「参考视频」列必填且要与 `@Video1` 一致 → ④ **每段每次授权**（第 1 段不覆盖第 2 段；**重生成、失败重试、换通道同样是新的一次花钱，都要重新申请**），授权记进 `gate-log.md` → ⑤ 执行前跑 `scripts/gate_check.py`，**台账对不上账不许提交**；生成后把 `credit_count` 回填「实际积分」列（报价准不准靠它对照）；生成完单独交付验收，通过才进下一段；全部通过后按序拼接成 `成片_无BGM.mp4` | `clip_<NN>.mp4`（**含模型原生人声**）+ `materials.txt` / `refs.md` / `cmd.sh` + `gate-log.md` + `成片_无BGM.mp4` |
| **⑤.5 音频验收（兜底配音）** | 即梦的输出**自带 AAC 音轨**（seedance2.5 原生音画同步），对白由提示词驱动模型生成。本阶段**逐段穿插执行**：`ffprobe` 验有音轨 → 抽音轨转写验有人声且是那几句台词。**只有模型确实不出人声时**，才用 `scripts/dub.py` 走 edge-tts 兜底配音 | 验收结论记 `gate-log.md`；兜底才有 `clip_<NN>_dub.mp4` |
| ⑥ BGM 适配合成 | **硬确认门：学员确认成片后才启动**。写 BGM 适配单（情绪曲线对齐钩子/转折秒数）→ 生成音频（即梦 Web / 曲库 / Suno）→ ffmpeg 以配音轨为底混音 | `成片_BGM版.mp4` |

> ⚠️ **关于对白（已实测更正）**：即梦的视频命令确实没有 `--audio` 这种"输出音频开关"，但**输出的 mp4 自带音轨**——seedance 2.5 是原生音画同步模型，声音是模型生成的。`ffprobe` 任意一个 `clip_<NN>.mp4` 都能看到 `h264,video` + `aac,audio` 双流。
>
> 所以**对白一律写进提示词，让模型自己说**（台词取自 `02-脚本/dialogue-map.md` 的改写列，逐句写「第几秒 + 谁 + 什么语气 + 台词」）。**千万不能把原句和改写句同时写进提示词**（模型会两句都念）。**千万别写"模型不负责出声/台词后期配音"**——模型会严格执行，结果就是环境声齐全、一句台词都没有的片（v2 就是这么翻车的）。后期配音（`scripts/dub.py`）只作为模型不出人声时的兜底手段。

## 安装

**方式一：npx 一条命令**（需要 Node.js 22.20+，会交互式选择安装到哪个 agent；`-g` 装全局）：

```bash
npx skills add https://github.com/liucheng-kerry/douyin-viral-clone -g
```

> WorkBuddy 用户注意：skills CLI 的 agent 列表暂不含 WorkBuddy。WorkBuddy 学员请用方式二，或用方式一装到任意 agent 后把整个 `douyin-viral-clone` 文件夹复制到 `~/.workbuddy/skills/` 下。

**方式二：git clone（WorkBuddy 推荐方式）**：

```bash
# 用户级（所有项目可用）
git clone https://github.com/liucheng-kerry/douyin-viral-clone.git "$HOME/.workbuddy/skills/douyin-viral-clone"
```

装完重启 WorkBuddy（或新开会话）即可生效，本技能自包含、无需安装其他技能。

## 快速开始（新电脑从零到能跑）

**第 1 步：装系统依赖**（Windows 用 PowerShell / Git Bash，macOS 用 Homebrew）

```bash
# ffmpeg（抽帧、转写喂音、混音）
winget install Gyan.FFmpeg          # macOS: brew install ffmpeg

# Python + whisper（口播转写）+ edge-tts（兜底配音，可选）
winget install Python.Python.3.12   # macOS: brew install python
pip install -U openai-whisper
pip install -U edge-tts             # 可选：模型没生成人声时才用

# 即梦 CLI（生图生视频通道，Windows 需在 Git Bash 里跑）
curl -s https://jimeng.jianying.com/cli | bash
```

装完 **重开终端**（PATH 才生效）。

**第 2 步：登录即梦**（OAuth 设备码，需在浏览器授权一次）

```bash
dreamina login
```

终端会打印授权链接和用户码，打开链接、核对用户码、完成授权；5 分钟内有效。之后 `dreamina user_credit` 能看到余额就说明登录成功。

**第 3 步：环境自检**（缺什么会直接告诉你装什么）

```bash
bash ~/.workbuddy/skills/douyin-viral-clone/scripts/check-env.sh
```

**第 4 步：开始用**——在 WorkBuddy 里说：

> 复刻这个爆款：<视频链接或本地文件路径>，主角换成 <你的选题>

## 使用

在 WorkBuddy 对话中说：

> 复刻这个爆款：<抖音/B站/小红书链接>，主角换成 <你的选题方向>

或直接给本地视频文件路径。工作流会在这些位置停下来等你：**复刻想法确认 → 脚本确认 → 每张图的参数确认（模型/分辨率/比例）→ 每张图单独授权 → 结构/数值质检 → 视频每段每次授权（含重生成/重试）→ 成片确认后再做 BGM**。其中**每一张图的参数与授权、每一次视频生成**都是花钱的硬门，说"全自动"也不会跳过。

## 设计原则

- **风格先于内容**：内容对了风格错了，观众一眼觉得假。原片的色调/质感/光线先被量化成「风格句」，再写进每一条图片与视频提示词；生成后对着原片同秒帧做三问质检，不过就改风格句重生成
- **一次生成一次授权**：生成真扣积分。图片每张出图前要让用户选定**模型版本/分辨率/比例**（张数恒为 1）；视频每段**每次**提交前都要单独拿到该次的许可并记进台账（`gate-log.md` / `image-gate.md`）。第 1 段的授权不覆盖第 2 段，**第 1 次的授权也不覆盖第 2 次**——重生成、失败重试、换参数、换通道都是新的一次花钱，都要重新申请。这样既避免批量误烧积分，也避免"跑完 5 段才发现方向错了"
- **保守执行**：每个付费动作前报参数、报余额、报预计消耗；**一张一张来**，第一张（主角定妆照）定画风，过了才出下一张；重跑前说清"上次为什么不行 + 这次要花多少"。**报价不用估的**——`quote.py` 从历史任务的 `credit_count` 反推真实单价（视频 720p=20 积分/秒、480p=12 积分/秒，图片 5.0/2k=3、5.0Pro/2k=8）
- **花完要回填，账才对得上**：台账里「预计积分」是报给用户的价，「实际积分」是生成后从 `dreamina list_task` 读回的真扣费。只报不回填，报价永远不知道准不准；`gate_check.py` 对"没回填"和"偏差超 30%"都报警，并在末尾汇总"这部片子到目前真花了多少"
- **参考视频不是默认开**：`--video` 传原片段能把动作/运镜/节奏直接给模型看，但它换的是另一档计费——计费秒数 = 参考片段 + 输出，所以片段越长越贵。于是每段都要让用户选：A 传（效果好、可能更贵）还是 B 不传（便宜、画面干净、复杂运镜靠文字赌），两档积分和效果差一起摆出来
- **成功判定严格**：`gen_status=success` 才算完成；中断后凭 `list_task` + 台账找回，跨对话的旧授权一律作废
- **质量来自拆解**：图片和视频的质量上限由逐帧拆解的颗粒度决定——每个物体、景别、机位、运镜、构图都要落到提示词里
- **声音不靠后期靠提示词**：即梦 seedance 2.5 原生音画同步，输出自带音轨。对白写进提示词（秒数+谁+语气+台词），模型自己说；验收只是确认它说没说。后期配音是兜底，不是常规流程
- **台词可重写，意思不能动**：逐字照抄会出戏（人物换了、话还是原来那句），彻底改意思又不是复刻。所以台词按档位重写，但五条锚点锁死——信息点、意图、情绪强度、人称话语权、句数落点。`dialogue-map.md` 逐句留证，`dialogue_check.py` 查形式，语义一致性由人读最终确认
- **一段提示词只出一张图，一个文件一个职责**：主角一张定妆照、每个场景一张定场图、每段一张首帧，不出候选、不出多面板多角度。全能参考把「一个文件」当一个素材读，一资产一文件才能让 `@Image1 = 人`、`@Image2 = 地` 立得住，也不会挤占编号、串味。少一张图丢的信息**用文字补**：侧脸轮廓与后背结构写进提示词，拍背面的段落再复述一次。写法按 `ai-drama-reference-art`：影视锚定、姿势=心理状态、DNA 物件、色卡融入叙述、MATERIAL TRUTH、AVOID 分类
- **还原度靠素材分工，不靠形容词**：全能参考能同时吃图片/视频/音频，但**一个素材只给一个职责**——角色图管长相、场景图管环境、原片帧管构图、原片段管动作运镜，分工写进提示词的 `@` 引用里。给满 30 张没有职责的图只会互相干扰；写"电影级""大片感"更是一点用没有
- **硬规矩必须能被机械验证**：`@` 编号对不上就是语义反转，人眼核对这句话说了三轮还是错。所以上传清单单独成文件（顺序=编号=传参顺序），`ref_check.py` 在提交前把「文件存在 / 编号连续 / `@` 集合一致 / 每个 `@` 有不取项 / 无致哑表述 / 两份正文一致 / 时长张数超限」全查一遍；花钱的门同样机械化——`gate_check.py` 在每份台账上查「有没有授权行 / 原话够不够具体 / 授权时间有没有倒挂 / 动作列有没有标成重生成 / 模型×分辨率组合是否合法 / 图片张数是否写了 1 / 场景与首帧有没有误用 1:1」，✘ 清零才许执行 `dreamina`
